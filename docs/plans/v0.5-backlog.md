# Implementation Plan: `gantt` v0.5 thin slice

## Overview

Build the v0.5 thin slice from `docs/ideas/gantt-skill-v0.5.md`: a Python CLI
(`gantt`) that creates and maintains a single-program Gantt chart in a Google
Sheet, with auto-cascading dependency math and critical-path computation.

The plan is sliced **vertically**: each slice ships a usable end-to-end
capability. Domain logic (DSL parser, working-days math, topo sort, critical
path) is built as pure Python with TDD, then wired through the CLI to the
Sheets I/O layer. After each slice the tool is dogfooded on the 90-day TPM
plan before the next slice begins.

## Architecture Decisions

- **Bundle layout mirrors `daily-ops`**: bundle-local venv at
  `tools/gantt/.venv/`, user state at `~/.config/gantt/{credentials,token,config}.json`,
  CLI on PATH at `~/.local/bin/gantt` (eventually via `claude-tool` manifest;
  for v0.5 we work directly in `~/Documents/gantt-chart/`).
- **Self-exec trampoline** in the CLI script (re-exec under `.venv/bin/python3`),
  copied verbatim from `daily-ops` — the comment about `sys.prefix` vs
  `sys.executable` matters under PEP 668.
- **Domain logic is pure Python**, no Sheets imports. Lets all the hard math
  (DSL parsing, topo sort, working-days, critical path) be unit-tested without
  network. Sheets layer is a thin adapter that round-trips dicts.
- **Sheet writes are full-tab rewrites** for the editable region (cols A–M)
  during `recalc`. Cheaper to reason about than diff-and-patch; gspread can
  do it in one batch update.
- **Formula timeline grid (cols N+) is set once** at `program new` and never
  rewritten. Conditional formatting handles colors. If a PM breaks the grid,
  v0.5's answer is "fix it manually" (schema repair is v1).
- **`gantt recalc` is the consistency boundary.** After any human edit in the
  sheet, you re-run `recalc` to re-cascade. The CLI is the only writer that
  understands dependencies.

#### Task 5: Predecessor DSL parser

**Description:** Parse the compact predecessor DSL: `1.2FS+3, 1.3SS-1, 2.0FF`.
Each entry is `<wbs_id><relation><signed_lag>?` where relation is one of
FS, SS, FF, SF and lag is optional working-days offset. Comma-separated.
Whitespace tolerant. Invalid input raises `PredecessorParseError` with a
useful message.

**Acceptance criteria:**
- [ ] `parse_predecessors("1.2FS+3")` → `[Predecessor(id="1.2", rel="FS", lag=3)]`
- [ ] `parse_predecessors("1.2FS+3, 1.3SS")` → 2 entries, second has `lag=0`.
- [ ] `parse_predecessors("")` → `[]`.
- [ ] `parse_predecessors("1.2XX")` raises `PredecessorParseError`.
- [ ] `parse_predecessors("1.2FS+abc")` raises `PredecessorParseError`.
- [ ] All four relation types tested at least once.
- [ ] Negative lag (`-2`) parses correctly.

**Verification:**
- [ ] Tests pass: `pytest tests/test_dsl.py -v` (≥10 cases).

**Review:**
- [ ] test-engineer — parser bugs cascade silently into wrong dates. Coverage
      should be paranoid.

**Dependencies:** None

#### Task 7: Topological sort + cascade engine

**Description:** Given a `Program`, compute the correct Start/End for every
task by topological sort over the predecessor graph. Apply each predecessor's
relation (FS/SS/FF/SF) and lag to derive constraints; the task's Start is
the maximum of all predecessor-derived constraints, falling back to its
manual Start if no predecessors. End = `add_working_days(Start, Duration - 1)`.
Detect cycles and raise `CycleError` listing the offending task IDs.

**Acceptance criteria:**
- [ ] Linear chain: 3 tasks with FS predecessors cascade correctly.
- [ ] Diamond (1 task with 2 predecessors): later end-date wins.
- [ ] Cycle: `1 → 2 → 1` raises `CycleError("cycle: 1 -> 2 -> 1")`.
- [ ] Lag respected: `1.1FS+2` adds 2 working days between predecessor end
      and successor start.
- [ ] SS relation: successor starts when predecessor starts (+ lag).
- [ ] FF relation: successor ends when predecessor ends (+ lag).
- [ ] Unanchored tasks (no predecessors, no manual start) raise
      `UnanchoredError` listing IDs.
- [ ] `cascade(program)` is idempotent: running twice yields the same result.

**Verification:**
- [ ] Tests pass: `pytest tests/test_cascade.py -v` (≥15 cases).

**Review:**
- [ ] test-engineer — this is the heart of the tool. Test paranoidly.
- [ ] code-reviewer — algorithm correctness; the SF relation in particular
      is rarely used and easy to get wrong.

**Dependencies:** Tasks 4, 5, 6

**Files likely touched:**
- `gantt-chart/gantt_lib/cascade.py`
- `gantt-chart/tests/test_cascade.py`
- `gantt-chart/tests/fixtures/programs.py` (shared fixture programs)

**Estimated scope:** M

#### Task 9: `gantt task add` / `update` / `delete`

**Description:** Three subcommands that mutate the data table of a program tab.
- `add`: append a new row, auto-assigning the WBS id from `--parent` (or
  next top-level if no parent). Flags map to columns. Does NOT recalc.
- `update`: locate row by id, set `--field=value` pairs. Does NOT recalc.
- `delete`: locate row by id, remove it. Refuses if any other task lists
  this id as a predecessor (force-delete is a v1 concern).

**Acceptance criteria:**

- [ ] `gantt task delete TPM90 1` refuses if task `2` has predecessor `1FS`.
- [ ] All three commands print a result line ending in ` ✓` (e.g.
      `gantt: task TPM90/1.2 added ✓`).
- [ ] None of the three triggers `recalc`. Stale Start/End is left for the

**Verification:**

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `gspread` round-trip latency unacceptable on 100+ rows | High — kills the workflow | Time the read+batch-write in Task 8 with a 100-row fixture. If >5s, add a row-range hint and consider Sheets API v4 batch instead of gspread. |
| Formula timeline grid breaks on column insert/copy-paste | Medium — degrades shareability | Document "don't insert columns N+" in `_Config`. v1 adds schema repair. |
| OAuth token expires silently mid-recalc and writes fail | Medium — user sees opaque error | Mirror daily-ops's first-run handler #3: detect `invalid_grant`, delete token.json, re-trigger consent with a single warning line. |
| Cascade engine has off-by-one on milestone (zero-duration) tasks | High — wrong dates erode trust | Task 11 includes explicit milestone-in-CPM test cases. |
| Predecessor DSL syntax friction → Jason avoids using predecessors | High — entire value prop collapses | Dogfood gate after Phase 4 explicitly checks this. If avoiding, switch DSL to verbose form before Phase 5. |
| Sheet shared with another PM, they edit cells, recalc clobbers their work | Medium — already accepted in v0.5 doc | Document explicitly in `SKILL.md` ("v0.5 is single-writer"). Treat as v1 work. |

## Parallelization Opportunities

- Tasks 5, 6 (DSL parser + working-days math) are independent and can be
  done in parallel.
- Task 4 (model) blocks 7 (cascade). 5, 6, and 4 can all run in parallel.
- Phase 1 must be sequential (each task depends on the prior).
- Phase 3 (Sheets I/O) blocks Phases 4–6 strictly.
